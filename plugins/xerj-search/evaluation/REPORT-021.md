# 0.2.1 格式、定位与读取修复重测

日期：2026-10-27。本轮只修插件适配和补读提示，保留四个原生工具、开关、项目范围及 Grep 回退。复用同一冻结语料、原 XERJ rc.99 索引、原 16 题及人工答案。没有启用向量检索、重建索引、查询改写或新增模型 API 调用。

结论：生产修复恢复了有效片段，并让五道题在相同读取预算内读到证据；文件命中没有提高。实际返回和读取字节有所增加，不能把质量提高等同于 Token 节省。

## 改了什么

- 格式解析只剥离已识别的定义/窗口标签、截断说明和完整页尾，保留普通方括号正文。原生预算去重或丢弃记录后，依据预算账目核对页尾数量，不把说明文字当成源码而误删命中。
- 保留匹配行与定义起点的区别。唯一片段按当前文件重定位；重复片段先看匹配行是否覆盖，再使用定义后唯一候选，无法消歧时返回 `line:null`。正文必须连续匹配当前文件，不能用省略号拼接不同区域。
- 每条命中增加 `readLine`，取已返回、已核验片段的中点。工具说明和 Skill 指示：正文足够时直接用；需要补读时先以它为中心 Read，未知位置先 Grep。批量预算移除正文时同步调整提示。插件没有新增自动读取或额外检索。

引文仍使用 `line/startLine/endLine`；`readLine` 是补读位置，不是引用位置。评测实际消费这项生产提示，保持前五个不同文件、±12 行和每文件 4 KiB；没有提示时沿用原命中行。这个读取策略变更明确记录为 `verified-readLine-v1`，没有修改旧成绩。

## 批量与保留的限制

同 16 题分四批、每批四题，显式 Map 一次，仍使用默认 1.5 秒。Map 返回三个索引，四批中英文功能题这一批耗时约 1,514 ms 后超时，四项均有独立 Grep 回退；其余批次正常。本轮没有放宽到历史控制试验的 5 秒，也没有反复重跑挑选成功结果。

该批量结果 `valid:false`，不用于证明批量收益。默认短超时下批量仍不稳定；逐项回退机制保留。不能把普通检索 48 次均正常推广为所有批量调用均正常。[完整批量结果](results/batch-native-021.json)
