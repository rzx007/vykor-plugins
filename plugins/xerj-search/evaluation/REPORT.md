# XERJ 基础 _search 适配器首轮实验

> 本文保留 0.1 历史结论；0.2 已完成原生四工具接入与同题集重测，见 [原生检索报告](REPORT-NATIVE.md)。

日期：2026-10-27。结论仅针对本次自写的基础 `_search` 适配器：保留为可关闭的可选插件，当前证据不足以支持默认启用这版实现。它对确切符号查找有用，在此次查询与片段处理方式下，中文需求定位和行为证据召回仍弱；真实模型实验观察到较少 Token，但样本小、预算耗尽较多。

范围修正：XERJ 本身还提供原生 code search、definition、map、批量搜索、索引预算、memory 与 Corpus Hub 工具。本次适配器只自行构造 `multi_match` 查询，再按固定窗口读取本地文件，没有使用原生代码搜索管线、定义查询的排序与去重、字段探查或批量检索。本文的低召回与 Token 数据不能作为 XERJ 完整 Agent 检索能力的结论。代码与资料搜索这一接入范围也允许使用上述原生只读工具；原生接入的收益尚未测量。

## 实现与接入边界

插件 `dev.vykor.xerj-search@0.1.0` 位于独立插件仓库，仅注册 `XerjSearch`。模型只提供问题和条数；地址、项目根和索引前缀由数据目录配置，默认未配置时不启用。配置 `enabled:false`、插件禁用或取消选择均可关闭这项能力。

调用从当前项目进入，只查询操作者绑定的本机索引；校验命中的实际文件仍位于项目内，再读取当前文本，返回有限片段与行号。索引仅为可重建副本。未提供写记忆、索引修改、上游反馈或服务安装工具；没有接入上游完整 MCP 工具列表。

失败、超时、无可用命中时返回可供内置 Grep 使用的参数；自然语言问题仍需提取关键词。真实宿主验证已串联执行“禁用的 XerjSearch → 宿主 Grep → 宿主 Read”，读取到目标文件。主动取消则直接中止，不擅自执行后续工具。计划模式或禁网策略阻止插件时，内置 Grep 保持可用。

当前只支持可核对的代码与文本资料；没有验证 PDF/Office、神经网络语义模式、跨语言模型、图谱或官方完整代码搜索管线。结论限定于本适配器与此次词法索引配置。

48 次插件调用均实际使用 XERJ，零服务错误、零自动降级。基线有 3 次超时和 3 次输出截断。插件 48 次均裁剪候选结果到有限返回范围，已保留截断标记；该批返回片段未触发单片段长度截断。独立核对 96 行评分和保存的原文窗口，未发现误算。另一次真实 disabled 配置回退到 rg 并读到人工证据。

基线获得人工挑选的 1–2 个正则，在全语料中搜索；这不代表模型自主选词或先缩小目录的性能。两组字节序列化格式不同，且插件自身另有 8 KiB 回包限制；字节减少不能换算成 Token 节省。重复查询受到操作系统和索引缓存影响，这批延迟不作为通用速度倍率。

## 真实模型 A/B：四题各两组

使用现有配置的 `deepseek / deepseek-flash`，经真实 Vykor QueryEngine、权限检查和 Grep/Read 执行。实验组额外激活本插件的真实独立工具进程。每类取第一道题，共四题；两组 system/user prompt 相同，仅可用工具不同，且提示有 XERJ 时先尝试、证据不足继续 Grep。每题独立会话，最多六次模型 HTTP、每次输出上限 1,024 Token，禁用重试，交替两组先后顺序。

| 项目 | 基线 | XERJ 组 |
| --- | ---: | ---: |
| Agent 任务 / 真实模型 HTTP | 4 / 22 | 4 / 22 |
| API 返回的输入 Token | 130,634 | 110,667 |
| API 返回的输出 Token | 7,183 | 7,037 |
| 输入与输出合计 | 137,817 | 117,704 |
| 工具调用 | 34 | 29 |
| 用满任务预算且未产出最终回答 | 3 | 2 |
| 产出定位答案 | 1 | 2（其中 1 份被输出上限截断） |

XERJ 组总 Token 少 **14.59%**。44 次 HTTP 均有原始 API usage；统计直接相加 provider 返回值，没有把本地阻断的额外逻辑 attempt 当作未返回 usage 的网络请求。没有推算价格或账单金额。

人工阅读最终答案：符号题两组都给出正确的 `packages/tools/src/search/grep.ts:8`；英文行为题和中文需求题两组均用满预算，没有最终答案；文档题仅 XERJ 组给出目标 `native-tools/README.md` 及相符的入口、取消与状态归属说明，但答案尾部因输出限制被截断。严格按完整未截断的最终答案计，两组均只有一题；路径提及和引擎 completed 状态不被当成完整任务成功率。

实验期间首个预算耗尽异常被宿主包装，初次脚本误判为 provider 失败并暂停。修正失败分类后只续跑未启动的五个任务，保留前三条结果及已发生的十四次 HTTP；没有重跑失败任务或挑选较好输出。原始记录保留 resume 时间。最终无 provider 服务错误、无重试，四次 XerjSearch 均成功。

这次观察说明检索有机会减少输入与工具往返；八次任务中五次耗尽预算，且样本仅四道题，尚无法据此判断质量或费用稳定改善。六轮上限、定制系统提示和小工具集也限定了结果的适用范围。
